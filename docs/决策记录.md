**关键设计选择**

1. **不使用 serde**：C# 持久化是裸键 JSON，标准解析器读不了；手写解析器同时支持 C# 与标准 JSON，写出保持 C# 兼容（双向互通）。
2. **无反射字段描述**：Rust 无反射，实体用 `fields()` 静态描述 + `get_field`/`set_field` 手写映射（约 10 行样板）。
   后续可选 proc-macro 派生（列入待办）。
3. **索引 ID 集合用 `BTreeSet`**：首版用 `Vec` + 线性去重，低基数字段（`Status` 只有 2 个取值）插入退化为 O(k)：
   10 万行时插入 20.8µs/行、更新 88µs/行。改 `BTreeSet` 后 **6.9µs/行、11.2µs/行**（插入 3.0×、更新 7.9×），迭代有序也让分页/范围顺序稳定。
4. **索引分页**：`find_by_page` 优先按有序索引取“前 N 条”（`O(page)`），索引未覆盖全表才退回全量排序；实测 9µs/页。
5. **写合并 + 不丢尾写**：写盘开始时先“取走”脏标记，写入期间的修改重新置脏，下一轮补写（C# 版 500ms 内直接 return，可能丢最后一次修改）。

**修复的 C# 缺陷（详见 `docs/与C#对照.md`）**

- 加载后 ID 计数器未修正 → 新增从 1 开始覆盖旧数据（Rust 取 `max(id)+1`）；
- 加载唯一冲突只警告、对象仍在表中但唯一索引缺失（Rust 跳过该对象）；
- `FindById` 前未触发文件加载（Rust 首次访问表即加载）；
- `NumericIndex`/`StringIndex` 范围查询全量遍历（Rust `BTreeMap::range`，`O(log n + k)`）；
- `FindByPage` 反射 + 全量排序（Rust 索引分页）；
- 通配符“ab”能匹配“abc”（Rust 修正为完整消耗文本）；
- 字符串索引 `Name` 未转义（Rust 转义引号/反斜杠、去换行）。
